따라서 exact match 대신 **탐지 패턴과 대체 문안**을 준다. 적용은 Codex 가 최신 `main` 에서 한다.

### 탐지

```

### 판정 기준

걸린 문장을 셋으로 나눈다.

| 구분 | 처리 |
| --- | --- |
| **진행 중** 이미지 후보 선택에 전수 대조를 요구 | **대체한다.** 아래 대체 문안 |

| 전수 대조가 아니라 **제외 조건**을 말하는 문장 | **유지한다.** 선행 노출·정본 불일치 배제는 그대로다 |

### 대체 문안 — 진행 중 선택 절차

```
이미지 호출 때마다 `references/IMAGE_INDEX.md` 의 맨 위 빠른 상황표를 먼저 본다.
맞는 줄이 있으면 그것으로 확정하고 아래 카테고리 목록은 읽지 않는다.
상황표에 맞는 줄이 없을 때만 목록으로 내려가 장소·실내외·시간·인물 외형·복식·병기·

**선택 기준은 하나도 바꾸지 않았다.** 장소·시간·인물·병기·행동 조건도,
선행 노출 금지도, "모두 부적합할 때만 생성 요청"도 그대로다. **훑는 범위만 줄인다.**

시작 규정 문서 경로가 아니다.** 그대로 넣으면 시작 예외가 가리킬 곳이 없어진다.

현행 정본 경로가 이미 두 곳에 명시돼 있으므로 별도 간접 참조가 필요 없다.

## 3. 신설 — 채팅 간 원본 회수 상한 (3시간 정지의 실제 원인)

`PUBLIC_IMAGE_DELIVERY.md` 의 `호출 상한과 중단` 절에 아래를 **추가**한다.

```
### 다른 채팅·외부 화면에서 원본을 회수할 때

- 이미지 생성 담당 등 다른 채팅에 올라온 원본 PNG 를 브라우저로 회수하는 경로에도
  상한을 둔다. 대화 목록 조회 10초 / 특정 대화 열기 15초 / 첨부 원본 1건 회수 30초 /
  이 경로 전체 절대 상한 90초.
- **이미지 응답에는 DOM 이 없어 "로드 완료" 신호가 오지 않는다.**
  화면에 떴는지로 완료를 판정하지 않는다. 회수 성공은 바이트를 손에 넣었는지로만 판정한다.
- 상한을 넘기면 즉시 중단하고 `회수 실패 — 원본 미확보` 로 보고한다.
  같은 경로를 자동 재시도하지 않으며, 대체 경로는 1회만 쓴다.
- **회수 실패는 자산 부재가 아니다.** 요청 조건과 대상 대화만 남기고
  사용자에게 원본 첨부를 한 번 요청한 뒤 다른 작업을 계속한다.
- 이 경로는 등록 파이프라인의 입력 단계이며, 이미 등록·커밋이 끝난 자산에는
  적용하지 않는다. **커밋이 끝났으면 그 시점에 작업은 완료다.**
```

그리고 같은 절 끝에 **완료 후 정지 방지**를 넣는다.

```
### 완료 뒤에는 재확인하지 않는다

- Git 등록 완료 판정은 ① blob SHA 일치 ② tree·commit 생성 ③ `main` fast-forward
  셋으로만 한다. 이 셋이 충족된 순간이 완료 시점이다.
- 완료 뒤 같은 자산에 대해 브라우저 확인·원본 재회수·표시 재검증을 하지 않는다.
- 사용자가 상태를 물으면 새 호출 없이 이미 확정된 커밋 해시로 답한다.
- 한 작업의 전체 벽시계 상한은 15분이다. 넘으면 완료분과 미완료분을 나눠 보고하고 끝낸다.
```

## 4. 바이너리 등록 — 절단 재발 방지

`c295ed5` 가 앞선 커밋의 절단을 복구한 건이다. 회신의
*"다중 blob 일괄 생성은 60초 이상 응답이 없어 중단"* 과 같은 사건으로 본다.

`바이너리 등록` 절에 아래를 보탠다.

```
- 커밋 직후 등록한 각 PNG 의 **바이트 수와 SHA-256 을 저장소에서 다시 읽어 원본과 대조**한다.
  이것은 브라우저 확인이 아니라 Git API 응답 값 비교이며 건당 5초면 끝난다.
- 불일치가 하나라도 있으면 그 파일만 다시 올린다. 전체를 다시 올리지 않는다.
- Base64 는 단일 blob 원칙이다. 도구 본문 제한이 있으면 읽기만 나누고 blob 은 하나로 만든다.
  blob 을 여럿으로 쪼개면 절단이 생긴다.
- 여러 파일을 한 번에 올릴 때 60초 안에 응답이 없으면 일괄을 포기하고 **파일별 커밋**으로 내려간다.
  연속 커밋이 되는 것은 정상이며 단일 커밋을 위해 재시도하지 않는다.
```

## 8. 요청 7 — 단계 구분 유지

```
생성 완료 → Git 등록 완료 → 공개 전달 완료 → 화면 표시 확인
```

3장의 신설 상한은 이 단계 구분을 **강화**한다.
회수 실패는 `생성 완료` 단계의 실패이지 자산 부재가 아니며,
`Git 등록 완료` 뒤의 확인 실패는 앞 단계를 되돌리지 않는다.
